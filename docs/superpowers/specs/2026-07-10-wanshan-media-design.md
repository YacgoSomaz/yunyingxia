# 万山自媒体设计说明

## 目标

构建独立的 Windows 桌面软件“万山自媒体”，用于本地管理提示词、配置用户自己的大模型 API，并完成选题分析、文案生成、文稿改写、标题生成、字幕切分和多平台适配。

## 边界

第一期只实现文案工作台，不包含账号登录、会员校验、远程授权心跳、自动更新、云端密钥同步、自动发布、数字人、AI 图片或 AI 视频。应用不在后台访问任何非用户主动配置的外部服务。

## 方案比较

1. 修改已解包应用：上线最快，但会继承旧应用的构建包、云端依赖和维护负担。
2. 全量复刻旧应用：功能覆盖最大，但周期长，且无法先验证本地优先架构。
3. 独立重建文案核心：保留清晰的工作流和可编辑提示词，使用新的代码、品牌和数据目录。第一期可用、可扩展，后续模块按需接入。

采用方案 3。

## 架构

- Electron 主进程仅负责窗口、本地 JSON 数据库、API Key 的系统级加密存储与 IPC。
- React 渲染进程提供工作台、提示词库、模型设置和本地记录库。
- 本地 JSON 数据库保存工作记录、提示词模板和非敏感设置；模型 API Key 使用 Electron safeStorage（Windows DPAPI）保存，不写入数据文件明文。
- LLM 调用只在用户点击生成时发生，目标为用户在设置页配置的 OpenAI 兼容端点；默认离线，不内置任何第三方域名。

## 核心模块

- 提示词模板库：11 个内置模板，带稳定 ID、名称、描述、变量定义、内容、创建时间和更新时间。支持复制、编辑、重置和变量预览。
- 模型设置：Base URL、模型名、API Key 的保存、连接测试与清除。默认地址为空。
- 文案工作台：主题、平台、风格、补充要求输入；生成大纲、扩写、润色、标题和字幕；每次生成保存为本地工作记录。
- 历史记录：按标题/主题检索，查看和删除本地工作记录。

## 内置模板迁移原则

原已解包应用中能读取到的 11 个场景被重新命名为万山模板：选题分析、文案大纲、场景扩写、文案润色、字幕切分、标题生成、平台适配、视频文稿改写、文本改写、视频画面扩写、画面中译英。模板以 JSON 文件随新应用发布，可在 UI 中恢复默认值。模板中的变量使用 `{{variable}}`，缺失变量渲染为空字符串。

## 安全与数据策略

- `contextIsolation: true`、`nodeIntegration: false`，preload 仅暴露白名单 IPC。
- 主进程验证全部 IPC 参数，不接受渲染进程传入任意路径或任意命令。
- 无自动更新、无统计、无授权、无启动后网络请求、无后台定时网络请求。
- 所有本地数据放在 Electron `userData` 下的 `wanshan-media.json`；API Key 只通过 safeStorage 加密保存。

## 验收

- 双击/开发启动后不出现登录页，也不产生网络请求。
- 未配置模型时明确提示先配置；配置后可以测试连接。
- 用户可编辑模板并预览变量替换结果；可恢复内置版本。
- 一次文案生成在本地留下可检索的记录。
- 构建后的应用窗口标题、目录与品牌均为“万山自媒体”。
